# Phase 2J 基线恢复设计

日期：2026-08-22

## 背景

当前 `F:\manhwa-reader` 保存了一份比 `.2E.bak` 更完整的 Phase 2J 工作版本，但 `index.html` 与 `app.js` 存在元素接线断裂。`app.js` 在初始化事件绑定阶段访问不存在的元素，导致整个脚本中断，书架和文件导入按钮因此没有响应。

本阶段保留当前主版本，不整体回退到旧备份；目标是恢复可启动、可点击、可导入的本地阅读基线。

## 目标

恢复以下最小闭环：

页面启动 → 书架显示 → 选择 PDF → 创建系列 → PDF 写入 IndexedDB → 阅读器打开 → 页面渲染 → 阅读进度保存。

## 范围

### 包含

- 修复 `app.js` 初始化阶段对缺失 DOM 元素的依赖。
- 补齐当前 JavaScript 明确使用的 `btn-set-cover`、`hidden-cover-input`、`rack-pager` 元素。
- 保留当前 Phase 2J 的书脊书架、封面、条漫检测、搜索排序、日夜主题、缓存管理和进度保存行为。
- 对启动、导入、阅读和进度保存执行最小验证。

### 不包含

- 不回退 `app.js` 或 `index.html` 到 `.2E.bak`。
- 不改变 IndexedDB 数据库结构或迁移逻辑。
- 不新增公网部署、Electron/Tauri、多设备同步或在线内容源功能。
- 不进行与本次恢复无关的大规模重构或 UI 重设计。

## 设计

### HTML/JavaScript 接线

优先补齐当前代码已经依赖的元素，并对可选元素采用安全绑定，避免单个缺失节点阻断整个应用初始化。动态创建的导入进度、模态框字段等元素继续由现有代码按需生成。

### 导入流程

保留 IndexedDB 作为本地存储。文件选择器返回 PDF 后，沿用现有“创建新系列/追加到已有系列”流程；`createSeries` 和 `importFilesToSeries` 继续负责元数据保存与 PDF 缓存。

### 验证流程

1. `node --check app.js db.js server.js`。
2. 启动 `node server.js`，确认 `http://localhost:8765/` 返回 200。
3. 浏览器确认页面无启动级 JavaScript 异常。
4. 选择一个 PDF，确认能够完成系列创建和阅读器打开。
5. 确认刷新后书架和阅读进度仍保留。

## 验收标准

- 页面加载后书架和按钮可交互。
- 点击“选择文件”能够打开系统文件选择器。
- 选择 PDF 后能够创建系列并进入阅读器。
- PDF 缓存写入 IndexedDB，章节能够渲染。
- 关闭并重新打开阅读器后，书架和阅读进度可恢复。
- 现有主题、搜索、封面和条漫相关代码不因本次修复被移除。

## 后续

基线恢复并通过人工验收后，再单独规划 Phase 2K 的功能修复；公网部署和桌面 App 作为后续阶段，不与本次恢复混在一起。
